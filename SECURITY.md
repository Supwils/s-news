# Security Policy

## Reporting a vulnerability

Please report security issues privately through GitHub's
[private vulnerability reporting](https://github.com/Supwils/swil-news/security/advisories/new)
rather than opening a public issue.

Include what you need to make the problem reproducible: the affected URL or
file, the request, and what you observed. A proof of concept is welcome but not
required.

Expect an acknowledgement within a week. This is a personal project maintained
by one person, so please size your expectations accordingly — there is no
bounty, and no SLA beyond a good-faith effort to fix what is real.

## What is in scope

- The deployed site, <https://news.supwil.com>.
- The maintenance endpoints under `app/api/`, in particular
  `POST /api/revalidate` and `POST /api/runtime/generate`.
- The daily content pipeline in `scripts/` and `.github/workflows/`.

## What is not

- **The digests themselves.** Everything under `NEWS/` is generated by an AI
  agent summarising third-party reporting. Inaccuracy, bias, staleness or a
  broken source link is a content bug, not a vulnerability — open a normal
  issue. See `LICENSE-CONTENT` for how that content is licensed.
- Findings from an automated scanner with no demonstrated impact. In particular,
  a `pnpm audit` listing is not by itself a report: most entries here are
  build-time transitive dependencies that no request can reach, since every page
  is statically generated and `next/image` is not used.
- Missing hardening headers that cost nothing to add — send a PR instead.

## Design notes relevant to security

Worth knowing before reporting, because each of these is deliberate:

- **The site is fully static.** Pages are prerendered at build time. There is no
  database, no user accounts, no sessions, no user-submitted content, and
  nothing to log in to.
- **`POST /api/revalidate` fails closed.** With `REVALIDATE_TOKEN` unset it
  rejects every request, and the token comparison is constant-time.
- **`POST /api/runtime/generate` executes shell scripts and is refused outright
  whenever `VERCEL` is set**, so it cannot run on the deployed site. Off Vercel
  it accepts `localhost` only, unless `ALLOWED_RUNTIME_HOST` says otherwise. The
  script is chosen by an allowlist lookup, never by string interpolation.
- **Digests are rendered as Markdown and their search excerpts are injected as
  HTML** (`components/search-page.tsx`, `components/search-modal.tsx`). Because
  the content originates from the open web, `scripts/validate-news-content.mjs`
  rejects any digest containing raw HTML tags, and the build fails if one
  appears.
- **Webfonts are vendored** under `app/fonts/` rather than fetched from Google at
  build time. That began as a build-reliability fix; it also removes a
  build-time network dependency.

## Secrets

No credential has ever been committed to this repository — verified across all
209 commits and both branches. `.env` and every `.env.*` are ignored, and
`.env.example` documents the variables without values.

If you believe a secret has leaked, report it privately as above. Do not open an
issue naming it.
